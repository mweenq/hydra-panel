# Changelog

## 1.0.0 — 2026-10-31

Первый релиз «как у аналогов»: подписка для Happ в нативном формате, оплата
в боте, редактор сообщений и привязка устройств по HWID.

### Подписка и клиенты

- **Формат `happ` переписан под нативный JSON Happ** — массив клиентских
  конфигов Xray: первый элемент «Автовыбор» (все серверы как `proxy-1…N`,
  балансер `leastLoad`, `observatory` с замером каждые 15 с), дальше по конфигу
  на каждое подключение с одним outbound `proxy`. Внутри: `log`, `dns`
  (UseIP + DoH), `inbounds` `socks-in:10808`/`http-in:10809`, `routing` с
  базовыми правилами и правилами из раздела «Маршрутизация».
- **Hysteria2 в JSON** — через диалект форка Happ: `protocol: "hysteria"`,
  `hysteriaSettings {version, auth, udpIdleTimeout}`, `alpn: ["h3"]`.
  Раньше hy2 в JSON не попадала вообще.
- Happ по умолчанию получает `happ`-формат; старый сохранённый `singbox` для
  Happ читается как `happ` (этот JSON Happ не понимает).
- Заголовок `routing: happ://routing/onadd/<base64>` с профилем маршрутизации
  Happ (DirectSites/DirectIp/ProxySites/ProxyIp/BlockSites/BlockIp).
- `routing.xray_rules()` научился `geosite`/`geoip` и `full:`/`domain:`.
- Конфиги провалидированы `xray run -test` (REALITY, XHTTP, Trojan gRPC,
  «Автовыбор» с балансером — без ошибок).

### HWID и устройства

- Таблица `devices` + сервис `services/devices.py`: устройство привязывается
  по заголовку `X-HWID`, хранится платформа, модель, версия ОС, IP и время
  последнего визита.
- Лимит устройств: общий в настройках (`hwid_limit`, 0 — без ограничения)
  и персональный у пользователя (`clients.device_limit`).
- Ответы подписки: `x-hwid-active`, `subscription-always-hwid-enable`, при
  отказе — `x-hwid-max-devices-reached`, `x-hwid-limit`, `x-hwid-not-supported`
  (те же флаги, что у Remnawave, Happ показывает по ним понятную ошибку).
- В профиле пользователя — карточка «Устройства»: список, блокировка,
  отвязка по одному и «отвязать все».
- В боте — кнопка «Устройства»: список с датами и отвязка в один тап.
- Настройка «оплата снимает привязки»: после зачёта платежа устройства
  отвязываются автоматически.
- На странице подписки видно «устройств 2 из 3».

### Оплата в боте подписок

- Тарифы: название, срок в днях, сколько ГБ добавить, цена, валюта
  (XTR / RUB / USD / EUR), вкл-выкл, порядок.
- Три способа: Telegram Stars (без провайдера), карта через платёжного
  провайдера, перевод вручную с подтверждением админом.
- Заявка приходит всем админам с кнопками «Подтвердить» / «Отклонить»;
  то же самое — в панели, в таблице заявок. Клиенту уходит уведомление.
- Зачёт продлевает срок от максимума (сейчас / текущая дата окончания),
  добавляет трафик, включает подписку и пересобирает конфиг нод.
- Страница «Telegram-боты → Оплата»: настройки, тарифы, заявки со статусами.

### Редактор сообщений бота

- Отдельная страница «Telegram-боты → Сообщения»: 48 текстов по группам
  (начало, подписка, устройства, инструкции, оплата, уведомления, кнопки).
- Переменные `{name}`, `{traffic}`, `{expire}`, `{plan}`, `{price}`, `{count}`…
  подставляются ботом; неизвестная переменная не роняет отправку.
- Хранятся только отличия от заводских текстов — после обновления панели новые
  формулировки подхватываются сами. Сброс по одному и «сбросить всё».
- Предпросмотр на тестовых данных, перезапуск службы не нужен.

### Напоминания об окончании

- Планировщик раз в 6 часов проверяет, у кого срок истекает в ближайшие N дней
  (настройка «Уведомления», по умолчанию 3 дня), и пишет в боте подписок.
- Одному клиенту — не чаще раза в сутки; текст правится в редакторе сообщений.

### Чего пока нет (в сравнении с Remnawave/Marzban)

- Шифрованные подписки `happ://crypt4/…` — ключ встроен в приложение Happ,
  серверу он недоступен.
- Группы/сквады (наборы подключений на пользователя) — сейчас подключения
  выбираются чекбоксами у каждого пользователя.
- Пробные периоды, промокоды, рефералка.
- Автосброс трафика по расписанию (день/неделя/месяц).
- Роли админов (сейчас один тип — полный доступ).
